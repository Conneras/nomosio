## 2. Πώς δουλεύει

```
Επισκέπτης ──► /kiniseis ──► rpc nomosio_moves()   (η βάση αποφασίζει τι ανοίγει)
     │
     ├─ Σύνδεση: email → 6ψήφιος κωδικός (Supabase Auth, αποστολή μέσω Resend)
     │
     ├─ «Συνέχεια στην πληρωμή» ──► plus-checkout ──► σελίδα πληρωμής Stripe
     │                                   (γράφει πρώτα τις δύο συγκαταθέσεις)
     │
     │  Stripe ──► plus-webhook ──► nomosio_members   (ΜΟΝΟ εδώ ανοίγει η πρόσβαση)
     │                          └─► email επιβεβαίωσης με ολόκληρους τους όρους (Resend)
     │
     ├─ «Διαχείριση συνδρομής» ──► plus-portal ──► σελίδα διαχείρισης Stripe
     └─ «Διαγραφή λογαριασμού» ──► plus-delete (αναλογική επιστροφή → ακύρωση → διαγραφή)
```

| Κομμάτι | Αρχείο |
|---|---|
| Πίνακες, κλείδωμα, συνάρτηση nomosio_moves() | `supabase/migrations/002_plus.sql`, `003_free_move_month.sql` |
| Τιμές, στοιχεία πωλητή, κανόνας «ενεργός» | `supabase/functions/_shared/plus.ts` |
| Πληρωμή / webhook / διαχείριση / διαγραφή | `supabase/functions/plus-*/index.ts` |
| Όροι μέσα στο email επιβεβαίωσης | `supabase/functions/plus-webhook/terms.html` ← `node tools/terms-email.js` |
| Περιεχόμενο κινήσεων | `data/moves.json` → `node tools/moves-sql.js --check` → `.qa/moves.sql` |
| Ιδέες που κόπηκαν | `data/moves-rejected.json` |
| Σελίδα | `index.html`, ενότητες `#kiniseis`, `#oroi`, `#plus`, υποσέλιδο |
| Βιβλιοθήκη σύνδεσης | `vendor/supabase-js-2.116.0.js` (από το δικό μας /assets, όχι από CDN) |
| Email με τον κωδικό | `docs/auth-email-templates.md` |

Κανόνες που δεν σπάνε:
- Η σελίδα δεν διαβάζει ποτέ πίνακα, μόνο τη nomosio_moves().
- «Ενεργός» = status active, trialing ή past_due, ίδια λειτουργία Stripe (test/live), χωρίς πλήρη επιστροφή χρημάτων. Γράφεται σε δύο σημεία: SQL και `_shared/plus.ts`.
- Το webhook απαντά 500 όταν αποτυγχάνει, για να ξαναστείλει η Stripe. 200 μόνο αφού γραφτεί, για διπλό γεγονός, ή για λογαριασμό που σβήστηκε.
- Πλήρης επιστροφή χρημάτων κλείνει την πρόσβαση αμέσως· μερική (αναλογική στη διαγραφή) όχι.
- Η δωρεάν κίνηση καρφώνεται για όλο τον μήνα (πίνακας nomosio_moves_free).
- Η ροή της συνδρομής δεν καλεί track(): το αναγνωριστικό συσκευής δεν δένεται με λογαριασμό.
- Οι τιμές ζουν στο `PLANS`. Κάθε «5 €» και «49 €» στη σελίδα και στους όρους πρέπει να ταιριάζει.
- Όλες οι functions έχουν `verify_jwt = false` σκόπιμα (τα νέα κλειδιά δεν είναι JWT): τον χρήστη τον ελέγχει ο κώδικας, το webhook την υπογραφή της Stripe.
- Όσο υπάρχει `{{ΣΥΜΠΛΗΡΩΣΗ: …}}`: το `node build.js` σταματά και το webhook δεν στέλνει email επιβεβαίωσης.
- Αλλαγή στους όρους ⇒ νέα έκδοση στο `TERMS_VERSION`, `node tools/terms-email.js`, deploy του plus-webhook.

## 5. Ενημέρωση κινήσεων

Σε κάθε «ενημέρωσε το Νομόσιο»: οι κινήσεις που πατούν σε νόμο που άλλαξε ξαναελέγχονται. Νέα κίνηση περνά τον ίδιο διπλό έλεγχο με τα τεκμήρια (γεγονότα + νομική διατύπωση), μετά `node tools/moves-sql.js --check`. Το `.qa/moves.sql` μπαίνει στη βάση ως migration, γιατί το execute_sql του Supabase MCP είναι μόνο για ανάγνωση, και κρατιέται αντίγραφο στο `supabase/migrations/` (πρώτο: `004_moves_seed_20260915.sql`). Μετά ελέγχεται ότι το md5 κάθε κίνησης στη βάση ταιριάζει με το αρχείο. Κανένα «benefit» δεν υπόσχεται αποτέλεσμα: λέει τι μαθαίνεις ή τι μπορείς να ελέγξεις. Η κίνηση για την κρατική αρωγή αναφέρει προθεσμία των πυρκαγιών Ιουλίου 2026· να ξαναγραφτεί με νεότερο παράδειγμα όταν παλιώσει.
